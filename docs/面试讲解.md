# 面试讲解

> **使用前提**：本文件中的所有说法都与代码和实验报告一致。
> **不得**把模拟结果说成线上实验，**不得**声称复现了任何公司的内部系统。

---

## 1. 三分钟项目介绍（逐字稿）

> **建议背下来，但语速放慢，重点在"我发现了什么"，而不是"我做了什么模型"。**

**（0:00–0:30 问题）**
"我做的项目叫 Budget-Aware Uplift Ads，研究的是广告预算有限时该把钱花给谁。
工业界最普遍的做法是按预测转化率排序——谁最可能转化就投给谁。
但这里有个结构性问题：**它分不清"因为广告才转化"和"不看广告也会转化"**，
后者会白占预算。理论上应该按**增量（uplift）**排序。
所以我的问题就是：**这两种排序到底谁更优？在什么条件下更优？**

**（0:30–1:10 数据与方法）**
"我用的是公开的 Hillstrom 数据集，6.4 万行，是三臂随机实验，
我实测核验过：三臂各约 2.1 万人，visit 率分别是 18.3%、15.1%、10.6%，
处理效应显著，而且没有缺失值。我做了两个对照：
一个是完全按响应概率排序的基线，一个是 S/T/X-learner 和类别变换四种 uplift 模型。
另外我**自己构造了一个半合成数据集，真实 CATE 已知**，
用它来验证我的指标实现、并且提供一个任何模型都超不过的 oracle 上界。"

**（1:10–2:00 结果——这是最值钱的部分）**
"结论分三层，而且**我自己推翻过一次**。

**第一层：在真实数据上，模型排序确实比随机好，但两种排序方式分不出高下。**
我第一轮只跑了单种子加自助法，结论是'所有策略都测不出来'，
还估算了'需要 136 万样本'。后来我做了 10 个种子重训加配对检验，
发现 **s_learner、response、t_learner 都显著优于随机**（配对差 +13.5 / +8.8 / +8.2，区间不含 0）。
原因是随机策略的收益**跨种子标准差就有 7.18**，数据划分本身的波动和要检测的效应同量级，
单种子必然测不出来。**所以那个 136 万的估算只对低效的比较设计成立——
问题不是数据不够，是设计不够有效。**
但核心假设仍然不成立：**s_learner 减 response = +4.63，区间 [−1.55, +10.81]，不显著。**

**第二层：在什么条件下 uplift 才真正有用？** 我构造了两个半合成场景：
一个基线和增量同向，一个反向。同向时，响应模型甚至略好（3.52 倍 vs 3.28 倍）——
**这就是'uplift 没用'这类说法的来源。**
但反向时，响应模型收益 10.5，最好的 uplift 模型 29.2，而随机是 −11.3——
**只有这个场景下，uplift 模型和随机的置信区间完全不重叠。**
所以结论是：**uplift 的价值取决于基线和效应的相关性，不是无条件更优。**

**第三层：投放节奏的效应比选人更大。** 不控节奏、让预算在早时段烧光，
收益只有均匀投放的 25%。而且当流量集中在晚间、早时段想花也花不出去时，
均匀投放会剩 17% 的预算花不出去，反馈控制器能追回到 3%。"

**（2:00–2:40 工程与踩坑）**
"工程上我踩过两个坑值得说。
**一个是我把结果列 visit 误当成了特征**，模型完美预测，
选中的人全是 y=1，增量收益恰好退化成 0——
因为当所有人都是正样本时，$Y_t=N_t, Y_c=N_c$，$G$ 恒等于 0。
**而 Qini 指标看起来完全正常。** 我改成显式特征白名单加断言，并加了回归测试。
**第二个是我自己写的 oracle 上界策略一开始输给了均匀投放**——
因为我按时段价值贪心，忽略了同一时段内用户质量的边际递减。
这说明**'上界'这种东西也需要审查**。"

**（2:40–3:00 反思）**
"这个项目最大的收获不是模型，而是**知道自己的方法什么时候不可信**：
排序指标会在总效应接近零时失效、小样本下的策略差异就是噪声、
模拟的收益不能当真实收益。这三条我都写进了文档的限制章节。"

## 2. 技术追问与回答要点

### 2.1 关于因果假设

**Q：你怎么保证 uplift 是可识别的？**
A：三个假设，且我逐条核验过前两个：
① **无未观测混杂**——Hillstrom 是随机实验，treatment 随机分配，
所以 $P(t|x)=P(t)$ 成立，我实测三臂规模 21307/21387/21306，随机化良好；
② **SUTB（个体处理稳定性）**——一次触达不会影响其他人的结果（邮件营销场景合理）；
③ **正性（positivity）**——每个人都有可能被处理。
**如果数据不是随机实验，我的 Qini 形式估计量就不成立**，
必须改用倾向性加权或工具变量。这一点我写在了 `budget.py` 的模块文档里。

**Q：为什么不用倾向性加权（IPS）？**
A：**因为数据是随机实验，倾向性是常数**（约 0.667），加权不会改变估计量。
如果我接 Criteo 或者观测数据，就必须补上。
这也是我在 `docs/后续迭代路线.md` 里列的一项。

**Q：你的"增量收益"到底是怎么算的？**
A：对选中集合 $S$：$G(S) = Y_t(S) - Y_c(S)\cdot N_t(S)/N_c(S)$。
它是 Radcliffe 的 Qini 形式。直觉是：用对照组来估计"如果不投放会有多少人转化"，
从处理组的实际转化里减掉。**我在 `tests/test_metrics.py` 里用手算例子验证过它**
（处理组 4 人转化 2 人、对照组 4 人转化 1 人 → 增量 = 2 − 1×(4/4) = 1）。

### 2.2 关于实验设计

**Q：为什么 5% 预算？为什么不做更多预算？**
A：做了。预算比例从 1% 到 20% 都跑了（见实验报告 §4.2a）。
**结果是不稳定的**：response 在 1%、2%、20% 时最好，5% 时最差。
**这种非单调性本身就是噪声的证据**——真实效应不会这样跳。
我把这一点写进报告，而不是挑一个对某个策略有利的预算来"证明"结论。

**Q：为什么不多种子重复？**
A：**已经做了**（`baua.cli multiseed`，10 个种子各跑完整流程）。
这一步直接改变了我的结论：单种子自助法说"所有策略与随机无法区分"，
10 种子**配对检验**（同种子内先减 random）则显示 s_learner / response / t_learner
显著优于随机（配对差 +13.5 / +8.8 / +8.2）。
教训是：`random` 的 gain **跨种子标准差就有 7.18**，
划分波动与待检效应同量级，所以单种子 + 自助法**功效不足**。
**我因此撤回了一个曾经写进 README 的估算（"需要 136 万样本"）——
那个数字只对低效的比较设计成立。**

**Q：半合成数据算不算"自己造数据自证"？**
A：它是**方法论工具**，不是结论来源，作用有三个：
① 验证指标实现（真实 CATE 已知，能算 oracle 上界）；
② 作为**阳性对照**——如果连强效应的半合成数据上都检不出差异，说明评测链路坏了；
③ 构造对照场景（aligned vs conflicting）来解释"为什么不同文献结论冲突"。
**我在报告里从不用半合成数据的结果替代真实数据结论。**

### 2.3 关于 pacing

**Q：pacing 的收益比选人策略还大，是不是说明选人不重要？**
A：**不能这么推论。** 两个原因：
① 两者的量纲不可比——pacing 的效应是"避免把预算烧在低价值时段"，
这是**减少浪费**；选人策略是"在同样的钱里挑更好的人"，这是**提升效率**。
我的模拟里价值曲线的振幅（peak_boost=1.8）是我设定的，
如果把它调小，pacing 的收益会随之变小；
② pacing 的结论**依赖于我模拟的时段价值曲线**，而选人策略的价值依赖数据本身。
**一个是模拟设定驱动的，一个是数据驱动的，不能直接比大小。**

**Q：feedback 和 uniform 的 gain_per_cost 谁高？**
A：**uniform 更高**（0.185 vs 0.172），但 feedback 的总收益更高（82.1 vs 73.8）。
原因是 feedback 为了把预算花完，会去触达边际价值更低的用户。
**所以如果 KPI 是 ROI 而不是总增量，naive uniform 反而更好。**
我把这个反直觉结论明确写进了报告——这也是面试官喜欢追问的点。

**Q：你的 pacing 控制器怎么设计的？**
A：比例控制器：`allowance = base + η × (目标累计消耗 − 实际累计消耗)`，η = 0.3，
并对单次调整做限幅。**我刻意只用 P 项**，因为反馈信号噪声大，加 I 会超调。
这和我在广告讲义第三讲里写的工程实践一致。
另外我修过一个差一错误：目标口径最初用 `(slot+1)/n`，
会让控制器在第 0 个时段就"自认为落后"，从而系统性超前消费。

### 2.4 关于指标

**Q：Qini 和 AUUC 有什么区别？你用哪个？**
A：Qini 用 $G(S)=Y_t-Y_c\cdot N_t/N_c$ 定义；AUUC 通常用"人均增量 × 前缀规模"。
两者形状相似但尺度不同。我两个都算了。
**更重要的是我发现它们在 conflicting 场景下都失效**——
所有策略的归一化 Qini 都是负的，包括最好的策略。
原因是那个场景的总效应接近零，归一化会放大噪声。
**所以我引入了第三个指标：预算约束下的策略价值 + 自助法区间**，
它是决策直接对应的量，不受归一化问题影响。

**Q：ECE 0.03 算好还是不好？**
A：**不算好，而且方向有问题，但我做了一件比"调好 ECE"更有意思的事。**
我报告的是分桶明细：在低分段（预测 0.058）实际是 0.089，**系统性低估约 30%**。
按广告业务口径，低估会导致出价偏低、拿不到量。
于是我加了一个 isotonic 校准器（在**训练集内部切出的独立验证集**上拟合，
绝不用评估集——那是另一种标签泄漏），结果 ECE 从 0.0298 降到 0.0112，降了 62%。

**Q：那校准之后策略变好了吗？**（这是我很希望被问到的追问）
A：**要分两种校准器、两种用法来说，这也是我觉得这个项目最有意思的发现。**
- **先看 isotonic（分段常数）**：
  对排序**有害**——它把评估集上 8020 个不同分数**压成了只剩 30 个取值**。
  一旦平坦区间跨越 top-k 的截断边界，并列就只能按索引任意打破，
  k=1920 时增量从 91.96 掉到 58.81，**降了 36%**。
  所以"单调变换不改变排序"这个直觉在**有并列**的情况下是不成立的。
- **换成 Platt（严格单调的 sigmoid 标定）就完全不同**：
  ECE 0.01197，和 isotonic 的 0.01121 几乎一样好，但
  **零并列、top-k 重合率 100%、各 k 的增量收益变化恰好为 0**。
  用 0.0008 的 ECE 代价换回全部排序分辨率。
- **所以最终结论是：用 Platt 一种分数就够，不需要维护两套。**
  isotonic 只在完全不依赖细粒度排序的纯阈值/分层场景才有意义。
- **另外校准对阈值决策确实很重要**：业务规则通常是"预测转化率低于 X 不投"这种**绝对值**。
  未校准模型在 τ=0.15 时只触达 52.8% 的用户，校准后是 60~64%，
  **差 7~11 个百分点**，增量收益差 17~25%。
  （不过这三者之间的差值落在本项目反复出现的噪声量级内，所以我只宣称
  "Platt 不损失排序"这条能从机制上说清楚的结论。）

**Q：你这个结论和文献里说的"校准很重要"矛盾吗？**
A：不矛盾，是**把它讲得更细了**。UpliftBench 那篇预印本说的是
"排序指标对符号阈值策略不充分、校准决策阈值能消除大部分选择悔恨"——
我的实测正好支持后半句：校准改善的确实是**阈值型决策**，而不是排序。
区别在于我给出了**机制**（isotonic 产生并列）和**代价的量化**（−36%）。

## 3. 如果被问"这个项目的不足"

**主动说，别等面试官挖**：

1. **样本量不足是根本约束**：需要约 136 万评估样本才能分辨 20% 的提升，
   而 Hillstrom 只有 6.4 万。**所以"真实数据上无法区分策略"这个结论，
   我无法判断是"方法无效"还是"数据不够"**——这是本研究最大的认识论局限；
2. **数据是邮件营销，不是广告竞价**：没有成本、预算、竞价字段，
   所有经济量都是模拟的。**结论只能用于方法学讨论，不能外推到投放决策**；
3. **没有多种子重训的方差分解**——**这一条已在本轮补齐**：
   见 `docs/实验报告.md` §4.7，10 个种子重训后报告 mean±std 与配对差异；
4. **没有做延迟反馈**（数据无时间戳）——而真实广告里转化延迟是核心难题；
5. **没有倾向性加权实现**（随机实验下不需要，但非随机数据下必须有）；
6. **响应模型的校准未做后处理**；
7. **conflicting 场景的效应强度是我选的**，不是从数据里估出来的。

## 4. 可改进方向（面试官问"你接下来会做什么"）

按优先级（详见 `docs/后续迭代路线.md`）：

1. **接入 Criteo Uplift（2500 万行）**——直接解决样本量问题。
   官方链接已核验但本机不可达，需要换网络环境；
2. **多种子重训 + 方差分解**，把"策略差异"与"模型训练噪声"分离；
3. **概率校准后处理**（isotonic / Platt），并检验校准是否改善策略选择
   （这正是 UpliftBench 提到的"校准阈值能消除大部分选择悔恨"）；
4. **倾向性加权 + 反事实评估**（IPS / DR），使方法可用于观测数据；
5. **预算感知的分配**：把第三讲里的拉格朗日视角（影子价格 λ）
   真正实现为"预算约束下的最优分配"，而不是当前的自上而下 top-k；
6. **延迟反馈建模**（DFM 思路），因为真实转化标签是不完整的。

## 5. 一句话总结（留给面试官的印象）

> "这个项目没有做出一个更准的模型，
> **但它做了一件我认为更重要的事：把一个被广泛接受的经验说法
> （"按增量排序比按转化率排序好"）放到了可检验的实验里，
> 并且诚实地报告了它在什么条件下成立、在什么条件下根本测不出来。**"
