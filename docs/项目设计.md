# 项目设计

## 1. 业务背景

广告主的预算永远是有限的。在预算约束下，平台/广告主面对的核心决策是：

> **把有限预算花在哪些用户身上，能带来最多的"本来不会发生、因为投放才发生"的转化？**

工业界最普遍的基线做法是**按预测转化率（响应概率）排序**：谁最可能转化就投给谁。
但这个策略有一个结构性缺陷：**它无法区分"因为广告才转化"与"不看广告也会转化"**。
后者（自然转化人群）会占用大量预算，却几乎不产生增量——
这正是业界流行的说法"**把广告投给了本来就会买的人**"。

Uplift（增量）建模的目标就是直接估计

$$\tau(x) = P(y=1 \mid x, t=1) - P(y=1 \mid x, t=0)$$

并按 $\tau(x)$ 排序分配预算。理论上它应当优于响应模型，但**现实中它经常不优**，
原因包括效应异质性太弱、样本量不足、模型误差与校准误差。

**本项目的价值不在于"再实现一次 uplift 模型"，而在于把这个问题做成一个可以量化回答、
并且能诚实报告"什么时候失效"的实验。**

## 2. 问题定义

### 2.1 形式化

- 候选集合 $\mathcal{U}$，每个用户 $i$ 有特征 $x_i$；
- 干预 $t_i \in \{0,1\}$（本项目：是否触达）；
- 结果 $y_i \in \{0,1\}$（本项目主结果：visit）；
- 预算 $B$，单次触达成本 $c$（**模拟量**），可触达人数上限 $k = \lfloor B/c \rfloor$；
- 策略 $\pi$ 给出分数 $s_i$，选择集合 $S = \text{Top-}k(s)$；
- 策略价值（增量收益）：

$$G(S) = \sum_{i \in S} \tau_i$$

在随机实验中，$G(S)$ 可用 §4.2 的 Qini 估计量无偏估计。

### 2.2 三个子问题（对应代码模块与报告章节）

| 子问题 | 研究内容 | 代码 | 报告 |
|---|---|---|---|
| Q1 谁更优 | 响应排序 vs uplift 排序（+随机、S/T/X-learner、类别变换） | `models.py`, `budget.py` | §4.1 |
| Q2 误差如何影响 | 分数加噪、样本量、预算比例、概率校准 | `budget.py`, `metrics.py` | §4.2 |
| Q3 节奏如何影响 | 何时花钱（前置 vs 均匀 vs 反馈控制 vs 上界） | `pacing.py` | §4.3 |

## 3. 数据

### 3.1 主数据集：Hillstrom（已实测核验）

| 项目 | 实测值 |
|---|---|
| 来源 | MineThatData E-Mail Analytics And Data Mining Challenge (2008), Kevin Hillstrom |
| URL | `http://www.minethatdata.com/Kevin_Hillstrom_..._2008.03.20.csv` |
| 规模 | 64,000 行 × 12 列 |
| 文件大小 | 3,964,977 字节（与 HTTP Content-Length 一致） |
| SHA256 | `0e5893329d8b93cefecc571777672028290ab69865718020c78c7284f291aece` |
| 缺失值 | 0 |
| 干预臂 | Mens E-Mail 21,307 / Womens E-Mail 21,387 / No E-Mail 21,306（近等量，随机化良好） |

**实测的列顺序**（与常见网上描述的顺序不同，本项目按实际文件记录）：

```
recency, history_segment, history, mens, womens, zip_code, newbie,
channel, segment, visit, conversion, spend
```

> 注意：`history_segment` 在第 2 列、`zip_code` 在第 6 列、`newbie` 在第 7 列。
> 代码在 `data.py` 的 `DOCUMENTED_COLUMN_ORDER` 中固定该顺序，
> 并在 `validate_hillstrom()` 中同时校验**列集合**（集合相等）与**列顺序**（不一致时告警）。
> 这是"不假定字段"的具体落实：第一次运行时正是因为假定的列序与实际不同而被校验器拦下。

**结果字段的实测分布**（按臂）：

| 臂 | visit | conversion | spend |
|---|---|---|---|
| Mens E-Mail | 0.1828 | 0.01253 | 1.4226 |
| Womens E-Mail | 0.1514 | 0.00884 | 1.0772 |
| No E-Mail（对照） | 0.1062 | 0.00573 | 0.6528 |

→ 处理效应显著（visit 提升 4.5～7.7 个百分点），且 `conversion=1 而 visit=0` 的行数为 **0**
（业务一致性通过）。

**用途与局限**：这是**营销邮件触达**的随机实验，不是广告曝光数据，也不含成本/预算字段。
本项目用它来检验"预算约束下的增量排序"这一方法学问题，**不宣称它等价于真实广告投放**。

### 3.2 半合成数据（已知真实 CATE）

`data.make_synthetic()` 生成：

```
x ~ N(0, I_d), t ~ Bernoulli(0.5)          # 完全随机化
mode="aligned"    : b = base + 0.4x0 - 0.3x1 + 0.2x2,  τ_logit = s( 0.8x0 - 0.6x3)
mode="conflicting": b = base + 1.2x0 - 0.3x1 + 0.2x2,  τ_logit = s(-0.5x0 - 0.4x3)
y ~ Bernoulli(σ(b + t·τ_logit))
```

**为什么必须有这个数据**（三个不可替代的作用）：

1. **验证指标实现**：真实 CATE 已知 → 可以检验 Qini/自助法是否与真值一致（`tests/test_metrics.py` 的
   `test_qini_perfect_ranking_beats_random` 等）；
2. **提供上界**：可以直接按真实 CATE 排序，作为任何模型都无法超越的 oracle；
3. **构造对照场景**：`conflicting` 模式让"高基线人群"与"高增量人群"反向，
   **这才是 uplift 建模真正的用武之地**；`aligned` 模式下响应模型几乎不输，
   可以用来解释"为什么有人说 uplift 没用"。

> 项目初期我们只在 `aligned` 模式下做过实验，结果响应模型表现很好（3.52× 随机），
> 这其实**掩盖了问题**。补上 `conflicting` 模式后才看出响应模型的结构性缺陷。

### 3.3 未使用的数据集：Criteo Uplift

官方链接已核验（见 `docs/论文与仓库调研.md`），但**本机不可达**（HTTPS 返回 404，
HTTP 连接超时），因此**不作为默认数据源**。代码保留 `load_criteo_manual()` 供手动放置后读取。

## 4. 方法选择及理由

### 4.1 为什么选这几个模型（而不是堆更多）

| 策略 | 类型 | 选择理由 | 局限 |
|---|---|---|---|
| `random` | 下界 | 任何策略都必须证明优于它 | —— |
| `response` | 响应模型（只在处理组训练 $P(y=1\mid x,t=1)$） | **工业界最普遍的基线**，是被检验的对象 | 不考虑"不投会怎样" |
| `s_learner` | 单模型 + treatment 特征 | 实现最简、样本利用率最高 | treatment 是单列特征，易被其他特征淹没 |
| `t_learner` | 双模型差分 | 最经典的 uplift 基线 | 两模型误差不相消；小样本臂不稳 |
| `x_learner` | 插补 + 倾向得分加权组合 | Künzel et al. (2019)；**两臂不平衡时通常优于 T** | 插补误差会被第二步放大 |
| `class_transform` | 类别变换（z-transformation） | 经典且实现廉价 | **要求两臂等量**，本实现对多数臂下采样 |

**没有做的事（明确记录）**：未实现 Causal Forest / DR-learner / R-learner / 深度 uplift 网络。
理由：4 小时窗口内无法公平比较，硬塞进来只会显得像"堆模型名"。
它们被列入 `docs/后续迭代路线.md`。

### 4.2 评估协议

**（1）排序指标：Qini / AUUC**

按分数降序做前缀，逐点计算 Radcliffe 形式的增量：

$$G(S_k) = Y_t(S_k) - Y_c(S_k)\cdot\frac{N_t(S_k)}{N_c(S_k)}$$

- $Y_t, Y_c$：前缀内处理组/对照组的结果和；$N_t, N_c$：人数。
- 归一化 Qini 系数：曲线除以终值后与对角线（随机基线）的面积差。
- **适用前提**：treatment 随机分配（Hillstrom 与半合成均满足）。
- **已知局限**：归一化会放大"总效应接近零"时的噪声；conflicting 场景下所有策略的 Qini 都是负数
  （见实验报告 §4.4），**排序指标无法用于该场景的策略选择**。

**（2）策略价值指标：预算约束下的增量收益 + 自助法区间**

这是本项目的主指标，因为它是**决策直接对应的量**。

$$G(\text{Top-}k) = Y_t(\text{Top-}k) - Y_c(\text{Top-}k)\cdot\frac{N_t}{N_c}$$

自助法：对评估集做 300 次有放回重采样，每次都重新选 Top-k 并计算 $G$，报告 2.5%/97.5% 分位。
**这一步是必须的**——本项目实测显示，不做区间估计会把噪声当成结论
（点估计相差 2 倍的两个策略，其 95% 区间几乎完全重叠）。

**（3）校准指标与校准后处理**

- 响应模型：在评估集处理组上算 ECE 与分桶偏差（`metrics.calibration_report`）；
- 半合成数据：预测 CATE 与真实 CATE 的分桶 MAE、Pearson 相关与偏差（`metrics.cate_calibration`）；
- **校准后处理**（`calibration.py`）：在**训练集内部切出的独立验证集**上拟合 isotonic 校准器
  （只用处理组样本，因为响应模型预测的是 $P(y\mid t{=}1)$）。
  评估分两个维度：
  ① **排序不变量检验**——单调映射是否真的保持 top-k 选择？（实测答案是"不一定"，见实验报告 §4.6）
  ② **阈值策略分析**——同一业务阈值（"低于 X 不投"）下，校准前后的触达规模与增量收益。
- ⚠️ 校准器**绝不允许用在评估集上拟合**，否则是另一种标签泄漏。
  本模块通过 API 设计（fit / transform 分离 + 显式传入验证集）强制这一点。

**（4）多策略差异的稳定性（多种子）**

- `multiseed.py` 对 N 个种子各跑一次完整流程，报告 gain 的**均值 ± 标准差**；
- 并做**配对比较**：同一 seed 内先算 $d = \text{gain}_{\text{策略}} - \text{gain}_{\text{random}}$，
  再对 $d$ 做 t 区间。配对能消掉"这一次划分的偏置"，方差显著小于直接比较两组均值。

### 4.3 预算与节奏的模拟假设（全部为模拟，不得当作事实）

| 变量 | 取值 | 含义 |
|---|---|---|
| `cost_per_treatment` | 1.0 | 单次触达成本（模拟单位）。**注意 `budget_ratio` 与人数上限的关系与它无关**：$k=\text{ratio}\times N$ |
| `budget_ratio` | 主场景 0.05，敏感性 0.01～0.20 | 预算占"全员触达成本"的比例，等价于"可被触达的人口比例" |
| `n_slots` | 24 | 把用户随机分配到 24 个时段 |
| `prime_slot_boost` | 1.8 | 黄金时段的价值系数（高斯凸起，峰值在 75% 处） |
| `supply_concentration` | 0（relaxed）/ 0.9（constrained） | 流量在时段间的集中度；0.9 表示早时段"想花也花不出去" |
| `damping` | 0.3 | 反馈控制器的阻尼 $\eta$ |

**价值与选人解耦**：每个时段内部按策略分数从高到低选人，
因此节奏模块只回答"**何时花**"，不回答"**花给谁**"。

**上界策略 `oracle_value_aware`**：按 $value_i \times v_{slot}$ 做全局 Top-k，
这是本模拟设定下的**真正边际最优**（已修正过一版错误实现：
早期按"时段价值"贪心会因为忽略时段内用户质量的边际递减而**输给均匀投放**）。
它需要预知时段价值曲线，**现实中不可实现**，仅用于量化"节奏优化"的空间。

## 5. 技术结构

```
src/baua/
  config.py       # 配置加载 + 日志（单一入口，命令行可覆盖）
  data.py         # 数据加载与校验、半合成生成器（含泄漏防线）
  models.py       # 响应模型 + S/T/X-learner + 类别变换
  metrics.py      # Qini / AUUC / 策略增量收益 / 校准 / 自助法
  calibration.py  # isotonic 校准器 + 阈值策略分析 + 排序不变性检验
  budget.py       # 预算约束分配与敏感性分析
  pacing.py       # 分时段节奏模拟（价值曲线、供给集中度、四种策略）
  multiseed.py    # 多种子重训与配对方差分解
  pipeline.py     # 实验主流程与产物落盘、绘图
  cli.py          # download / inspect-data / smoke / run / multiseed
tests/            # 40 项单元测试（针对真实行为，无 mock 断言）
scripts/          # PowerShell 与 bash 一键脚本
configs/          # default.yaml（全量）与 smoke.yaml（冒烟）
```

**设计原则**

1. **不做隐式行为**：不在 import 时下载数据；路径全部来自配置；
2. **可复现**：所有随机性由 `seed` 控制；`summary.json` 记录配置快照与运行环境；
3. **模拟与观测严格分离**：所有模拟量在代码注释、文档与产物字段中显式标注
   （如 `pacing_grounded` 字段直接标明节奏结论是否由真实 CATE 支撑）；
4. **不假装工程化**：没有 Docker、没有分布式、没有 API——
   因为它们不在 4 小时窗口内且不影响研究结论。在线 API 列入后续路线。

## 6. 已知的坑（本项目实际踩到并修复的）

记录在这里，因为它们比"顺利的部分"更有信息量：

1. **标签泄漏（最严重）**：特征列表最初用"排除法"（排除 treatment/y/arm），
   结果把 `visit/conversion/spend` 也当成了特征。模型"完美预测"，
   选中集合全部 $y=1$，导致增量收益**恰好退化为 0**（$Y_t=N_t, Y_c=N_c \Rightarrow G\equiv 0$），
   而 Qini 依然很好看。**修复**：改为显式白名单 + `assert_no_leakage()` 断言 + 回归测试。
2. **类别列 dtype 丢失**：只在临时副本上 `astype("category")`，拆分后仍是 `object`，
   LightGBM 直接报错。**修复**：在拆分前的原始 frame 上转换。
3. **反馈控制器的差一错误**：目标口径用 `(slot+1)/n_slots` 会让控制器在第 0 个时段就"自认为落后"，
   系统性超前消费。**修复**：改为 `slot/n_slots`。
4. **错误的 oracle 上界**：按"时段价值"贪心会输给均匀投放，不是一个合法的上界。
   **修复**：改为按 $value_i \times v_{slot}$ 的全局边际最优。
5. **把噪声当结论**：点估计相差 2 倍的策略，置信区间几乎完全重叠。**修复**：引入自助法区间，
   并把它写进 README 的核心结论。
